# PayPilot 付款 Agent 设计说明（评审稿 v0.8）

## 目标

PayPilot 根据自然语言指令查询供应商账单并创建付款。目标环境为企业财务系统，单笔付款可能需要人工审批。

## 当前设计

1. 使用 ReAct 文本协议。系统提示词要求模型输出 `Action: create_payment` 和 JSON 参数；运行时从文本中提取 JSON，未配置 JSON Schema。
2. 系统提示词写明：“金额超过 5000 元必须先获得用户批准。”审批由模型在对话中判断，执行器不检查审批记录。
3. 状态包含 `thinking`、`acting`、`done`、`error` 字符串。主循环每轮直接给状态赋值，没有单独的状态转换表。
4. 所有工具共用一个异常处理器：无论网络超时、HTTP 403、参数错误还是余额不足，均重试 5 次，固定间隔 1 秒。
5. `create_payment` 超时后也按相同策略重试。请求没有幂等键；外部银行接口文档未说明是否支持幂等。
6. 任务只在调用工具之前保存 Checkpoint，字段包括任务 ID、消息、当前步骤和状态。进程重启后从最近 Checkpoint 继续执行当前步骤。
7. 全局最大步数为 20，所有任务共用。没有 Token 或费用预算，没有单次模型、单次工具和整个任务超时配置。
8. UI 取消按钮会把状态改为 `cancelled`，但正在执行的 `create_payment` 不接收取消信号；主循环下一轮仍按当前步骤调度。
9. 为便于排查，日志记录完整工具参数，包括供应商银行账号、付款备注和用户身份证明字段。
10. 如果付款工具最终没有明确结果，运行时将错误交回模型，让模型“根据已有信息给出最可能的处理结果”。
11. 当前没有规划或并行子任务；账单查询与付款在同一个主循环中完成。
12. 测试仅包含一次成功付款的 Demo 截图，没有自动化故障测试。

## 已知外部条件

- 银行可能出现“服务端已受理，但客户端未收到响应”的情况。
- 财务系统可以提供付款申请单号，但当前设计未使用。
- 供应商账单查询是只读操作，创建付款是不可逆高风险操作。
