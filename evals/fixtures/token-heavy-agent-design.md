# AssistFlow 工单助手 v2.3 设计文档（内部评审稿）

> 产品：AssFlow 团队 · 2026-09 · 密级：内部

## 1. 背景与任务

AssistFlow 是公司内部客服工单助手，接入 IM 后日均处理 4000+ 会话。主要功能：

1. **工单判责**：读取工单与订单数据，判断责任归属（退款/补发/驳回），给出处理建议；
2. **周报生成**：每周一上午 10 点汇总上周工单，生成约 8000 字 Markdown 周报；
3. **知识问答**：员工咨询退款政策、物流规则等。

近三个月账单环比上涨 240%，管理层要求做一次架构审查。

## 2. 总体架构

主 Agent 负责全部流程调度：接收消息 → 读取工单数据 → 识别工单类型 → 分发任务给子 Agent → 接收结果 → 生成回复 / 汇总周报。

- 主 Agent：负责数据读取、类型识别、任务分发、结果汇总与排版；
- 子 Agent A（判责推理）：分析工单与订单，输出责任判断；
- 子 Agent B（知识问答）：基于内部知识库回答政策问题。

主 Agent、子 Agent A、子 Agent B **统一使用 GPT-5.2-Pro**（公司统一采购的旗舰模型，写死在配置里），保证效果一致。

## 3. Prompt 组装

每轮请求按以下顺序组装（伪代码）：

```python
messages = [
    {"role": "user", "content": f"[{now()}] 用户 {user_id} 说：{user_text}"},   # 用户消息放最前，方便模型第一时间关注
    {"role": "system", "content": f"当前时间：{now()}\n操作员：{user_name}\n{ROLE_PROMPT}（约 6000 字角色、流程与规范说明）"},
    {"role": "system", "content": tools_rendered},     # 工具描述
    *history,                                          # 历史对话
]
```

说明：

- 用户消息固定放第一条，是 v2.1 改版时为了提升首字响应速度做的调整；
- System Prompt 首部拼接当前时间和操作员信息，便于模型感知上下文；
- `tools_rendered` 每次请求从 MCP 网关**动态拉取全量工具列表**渲染（网关返回什么顺序就按什么顺序渲染）；
- 每轮对话结束后，主 Agent 会对 `history` 做一次**摘要压缩**：调用一次模型把此前全部历史改写成一段 500 字摘要并替换原历史，控制上下文长度（v2.2 上线的优化项，上线后上下文确实变短了）。

## 4. 工具清单

通过 MCP 网关接入 **43 个工具**（工单系统 12、订单系统 9、物流 7、退款 6、知识库 3、IM/通知 4、其他 2），工具描述平均约 700 Token，**全部工具每轮全量注入**。

高频使用的工具其实只有 6 个（查工单、查订单、查物流、创建退款单、查政策、回填工单），其余 37 个月均调用不足 5 次。模型偶尔会选错工具（月均约 40 次调到废弃接口 `getOrderDetailLegacy`）。

### 4.1 订单查询的数据流

`queryOrderFull` 工具返回订单**完整明细表**（含全部商品行、优惠、日志，平均 300 行 JSON）。判责时主 Agent 在对话里要求模型"从上表中筛选出状态为待收货的行"，子 Agent A 再基于同一张表做二次筛选，一张表平均在上下文里出现 3 次。

## 5. 记忆与知识库

- 长期记忆存放在 `memory/` 目录（12 个 Markdown 文件，共约 20000 Token：判责案例、话术库、历史周报要点、团队规范等）。**每轮请求前全量读取并注入 System Prompt 尾部**；
- 知识问答子 Agent 同样全量读取 `kb/` 目录（8 个政策文档，约 30000 Token）。

## 6. 输出与报告

- 所有生成不设 max_tokens（曾因截断被投诉，v2.1 起移除该限制）；
- 周报每周全文重新生成（约 8000 字 Markdown，含大量每周不变的模板文字与章节结构），格式与排版完全由模型生成；
- 工单回复输出自由文本，下游系统再用正则从文本里抠字段（经常抠错）。

## 7. 监控与预算

- 网关侧记录每次调用的**总 Token 数与耗时**，按天汇总到看板；无按功能模块的成本归集，无缓存命中相关指标（采购时听说模型支持 Prompt 缓存，未单独配置）；
- 预算控制：每人每日 50 次调用硬上限，达到后当日禁用（有测试）；
- 模型调用失败重试 2 次；工具调用超时 30 秒，超时后重试 1 次。

## 8. 已知问题（团队自查）

1. 月账单从 2.1 万涨到 7.2 万，涨幅集中在输入侧；
2. 摘要压缩上线后，偶尔出现"忘记用户昨天说过的特殊备注"，需要重新上传工单；
3. 43 个工具的描述维护成本高，废弃工具下线不及时。
